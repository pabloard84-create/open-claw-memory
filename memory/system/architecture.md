# Memory Architecture

## Goal
Tener memoria de largo plazo confiable, recuperable y útil para trabajo proactivo.

## Layers
1. `MEMORY.md` — memoria curada y estable.
2. `memory/preferences.md` — preferencias del usuario.
3. `memory/decisions.md` — decisiones importantes.
4. `memory/daily/YYYY-MM-DD.md` — eventos y trabajo diario.
5. `memory/projects/*.md` — estado por proyecto.
6. `memory/people/*.md` — información relevante por persona.
7. `memory/timeline/YYYY/MM.md` — línea de tiempo mensual.
8. `memory/system/*.md` — reglas, arquitectura, playbooks.

## Operating rules
- Si una tarea se alarga o cambia de objetivo, crear checkpoint.
- Si una conversación produce una decisión importante, escribirla.
- Antes de responder sobre pasado, decisiones, preferencias o estado, consultar memoria.
- Consolidar periódicamente diarios en memoria estable.

## Proactive model
- Heartbeats/checks para revisar contexto y pendientes.
- Resúmenes periódicos (diario/semanal/mensual).
- Avisar proactivamente solo cuando haya valor claro.
